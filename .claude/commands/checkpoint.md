# Checkpoint Command

This command is for creating a small report of what happened and why it happened along with evidence for each milestone completed.

# Command Instructions

Update the 'Resume here' box in docs/PLAN_v2.md with a short summary explaining where in the project we are and where to pick up from. (The purpose of 'Resume here' section is to tell a new chat session or someone new in the team, what in the project has been built and what the next part of the project is to be built)

Everything below is to be appended to the file 'docs/checkpoint_report.md':

1.  Add section header 'Milestone < milestone number here > Completed'
2.  Provide a summary of the work done in the milestone in plain language.
3.  Add subheading 'Why' — explain the reasoning behind anything decided independently this milestone (a library pick, a file structure, a naming choice). If nothing was decided independently, write "nothing decided independently this milestone."
4.  Add subheading 'Files Created/Modified:'
5.  Under the subheading, write down which files which were modified or created and written in as well as their location. Add a small description on what was written in them. Eg. : lessons/recursion.py (new): < Small description of what is written in the file>
6.  Add subheading 'Uncertain / worth double-checking' — anything unsure about goes here explicitly. If nothing, write "none this milestone."
7.  Add the subheading 'Screenshots', under that include all screenshots. If there's nothing visual (e.g. config/infrastructure work), include the terminal output proving it works instead — e.g. tests passing, or the CI check showing green on GitHub.
8.  Create subheading 'Github Commands for this milestone' and under that subheading write the exact git commands that the owner needs to run.
9.  End with a single sentence mentioning which milestone is next, if a phase has completed mention which one and which phase is going to start.
