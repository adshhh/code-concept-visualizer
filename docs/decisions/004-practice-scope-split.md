# 004 — Practice's scope splits by consumer: 18 programs at m13, 6 programs + hint level at m14

**Date:** milestone 13a (planning, before any code)
**Status:** accepted — no section reopened; D27, D32 and D33 are all unchanged in content, only
re-sequenced across milestones
**Narrative version:** `docs/DESIGN_RATIONALE.md` §35

## What changed

Three things that §9 grouped under "Practice" now land at **milestone 14** rather than 13:

1. **6 of D27's 24 authored programs** — binary search and bubble sort, 3 levels each.
2. **AC-9.12** — "program difficulty and hint level are independently selectable."
3. **Building a real parse tree**, which §9 assumed already existed.

Milestone 13 authors the other **18** programs (the 6 basics × 3 levels) and ships the
program-difficulty selector alone. The Build milestones table's row 14 was rewritten to own all
three explicitly, and AC-9.11/AC-9.12 carry inline `v2 re-sequencing` annotations pointing here.

## Why it changed

**Each of the three had no consumer at milestone 13.**

D33 bars reverse mode from the algorithms ("reassembling bubble sort from shuffled lines is a
memory test, not an exercise"). Flowcharts are the only other Practice exercise type, and they are
milestone 14. So binary search's and bubble sort's 6 programs could have been *authored* at 13 but
never *exercised* or *verified against a UI* there — they would have been six files whose only
check was "valid subset, runs clean," sitting unused for a milestone.

D32 defines hint level as **how many flowchart cards start pre-filled**. Milestone 13 has no
cards. A hint-level selector shipped there would have been a visible control that changed nothing —
the kind of thing that looks like a feature in a screenshot and is a lie in the product.

The third is different in kind: it is not a scheduling choice but a **correction**. §9 says the
flowchart is "generated by parsing the program (§1 validator already parses it)" and that "the
diagram is built by walking the same structure the validator already produces." `src/subset/
parser.ts` produces no such structure. It is a recursive-descent **recognizer** — every method
returns `void`, and `parseSuite()` recognizes block nesting at the moment it consumes
INDENT…DEDENT and discards it. The only thing that survives parsing is a pass/fail verdict plus one
line number. Reverse mode does not care (D34 defines its blocks as "the program's own lines,
shuffled," and the tokenizer already emits per-line structure). **Flowcharts care completely.**
Recording it here means milestone 14 plans to build a tree, rather than discovering mid-build that
the thing it was told it could reuse does not exist.

## The failure this is guarding against

The milestone-1 audit found "seven pieces of promised work that no milestone owned." That is the
exact shape of what deferring work creates if the deferral is only spoken. So the deferral is
written into the milestone table's row 14 — the operative definition of what a milestone contains —
not only into the acceptance criteria it came from. AC-9.11 is now explicitly **partially closed at
m13 and fully closed only at m14**, rather than being quietly reported as met.

## Which sections this invalidates

None. D27's program count (24), D32's two independent settings, and D33's reverse-mode scope are
all unchanged — this moves *when* they are satisfied, not *what* they say. §9's two claims about
the validator producing reusable structure are noted as inaccurate-as-written and corrected in row
14; the criteria themselves (AC-9.18–9.21) are unaffected, since they specify the flowchart's
output, not the mechanism.

## Trade-offs

If D28 cuts flowcharts whole, AC-9.11 never fully closes and AC-9.12 is never demonstrated — v1
would ship 18 Practice programs, not 24, and one selector, not two. That is the correct outcome
rather than a regression: both items exist *to serve flowcharts*, so a cut that removes flowcharts
should remove them too. The alternative — authoring 6 programs and a dead selector first, to keep a
criterion technically green — would leave v1 carrying content and UI for a feature it does not
have.
